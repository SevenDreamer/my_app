# Distributed Hermes Agent — 项目愿景

## 核心理念

让每部手机成为一个 AI Agent 的物理实体（Embodied Agent），多个 Agent 节点组成分布式网络，自主协作、持续进化。

## 愿景场景

```
主手机 (Agent Alpha)          副手机 (Agent Beta)
┌──────────────────┐          ┌──────────────────┐
│ 我直接与 Alpha 对话 │          │ 无人值守，自主运行  │
│                  │          │                  │
│ Agent Alpha      │←─ 自主 ─→│ Agent Beta       │
│ 控制本机          │  协作/同步 │ 控制本机           │
│                  │          │                  │
│ 打开App/发消息/   │          │ 拍照/传文件/执行   │
│ 操作界面          │          │ 定时任务          │
└──────────────────┘          └──────────────────┘
```

- 主手机：用户与 Agent Alpha 交互，Alpha 作为主控 Agent
- 副手机：Agent Beta 独立运行，可被 Alpha 远程调度，也可自主行动
- Agent 之间通过中继服务器自主通信、协作、同步状态

## Agent 的"身体"——手机操控能力

Agent 不只是聊天机器人，它能感知和操作物理世界（以手机为媒介）：

| 能力层级 | 说明 | Android | iOS |
|---------|------|---------|-----|
| L0 只读状态 | 在线、电量、存储 | ✅ | ✅ |
| L1 被动响应 | 查文件、读信息 | ✅ | ✅ |
| L2 主动操作 | 发消息、传文件 | ✅ | ⚠️ 受限 |
| L3 屏幕控制 | 无障碍服务操作 | ✅ | ❌ |
| L4 完全控制 | 安装App、系统设置 | ⚠️ 需确认 | ❌ |

默认只开放 L0-L1，L2+ 需要主手机确认授权。

## 本地模型（副手机特有）

副手机部署轻量本地模型，实现"边缘智能"：

- **快速响应**：简单问题本地直接回答（低延迟、省流量）
- **意图分类**：判断消息是否需要处理、紧急程度
- **离线可用**：网络断开时仍可工作
- **自学习进化**：交互数据积累 → 记忆 + 技能沉淀 → 服务器微调 → 模型下发更新

### 手机本地 LLM 可行性

| 手机 RAM | 可用模型 | 量化后大小 | 推理速度 |
|----------|---------|-----------|---------|
| 6GB | Qwen3 1.5B / Phi-4 mini | ~1GB | ~8 tok/s |
| 8GB | Qwen3 4B / Gemma 4 E2B | ~2.5GB | 10-15 tok/s |
| 12GB+ | Qwen3 4B / Llama 3.2 7B | ~4GB | 15-30 tok/s |

推荐配置：Q4_K_M 量化 + KV cache q4_0

## 关键限制

- **iOS 无法后台持续运行**：只能推送驱动（APNs 唤醒 → 处理 → 休眠）
- **Android 前台服务可保活**：但国产 ROM 有额外杀后台策略
- **Agent 间不能直连**：NAT/IP 变化/息屏断网，必须经中继服务器

# my_app — 愿景与产品定义

> 状态：草案 v0.1（2026-10）｜名字暂用 my_app，品牌后议

## 一句话定位

**个人工具箱**：一个完全属于自己的多功能应用——从实用小工具起步，走向"个人数字中枢"。

## 图景（北极星）

设备之间（手机 / 电脑）通过蓝牙、Wi-Fi、NFC 自由通信与组网；内容从各处
（系统分享、微信生态、博客 / GitHub）汇聚进来；AI 通过 MCP 协议随时接入。
最终形成「一台设备控制另一台、所有设备为我服务」的个人设备网络。

## 功能板块

### A. 工具集合（已起步）

- 记事本（sqflite 本地库，已有）
- 机器人眼睛（玩具 / 演示性质，保留黑底个性化视觉）
- 数据库管理（规划）
- GitHub / 博客查询（规划）

### B. 设备通信与组网（核心方向）

- 近场通信：蓝牙（BLE）、Wi-Fi Direct / 局域网、NFC
- 设备发现、配对、点对点消息
- 多设备组网（拓扑、消息路由）
- 场景：两台手机互通 → 一台手机控制另一台

### C. 内容聚合

- 系统分享接收：其他 App 分享内容进来（存入笔记 / 收藏）
- 微信生态联动：小程序 / 公众号（形态待探索）
- 博客 / GitHub 内容的查询与展示

### D. AI 与 MCP 基础

- MCP 协议基础层：工具注册、调用通道、能力描述
- 为后续 agent（小七）接入预留接口

### E. 设备控制（远期）

- 电脑控制手机（桌面端为控制端）
- 手机控制手机（依赖 B 板块的组网能力）

## 平台能力矩阵

移动端优先，桌面互补：**通信与随身在手机，管理与控制在电脑**。

| 能力 | 移动端 | 桌面端 |
|---|---|---|
| 工具集合 | ✅ | ✅ |
| 蓝牙 / NFC 组网 | ✅ 主战场 | ➖ |
| Wi-Fi 发现 / 通信 | ✅ | ✅ |
| 系统分享接收 | ✅ | ⚠️ 受限 |
| 控制手机 | ➖（被控端） | ✅（控制端） |
| AI / MCP 基础 | ✅ | ✅ |

实现要求：功能注册时声明平台能力（支持 / 受限 / 不支持），
界面按平台显示或禁用入口，不允许出现"点进去才发现不能用"。

## 边界（暂不做什么）

- 不做社交、多用户、云同步（起步阶段纯本地、单人使用）
- 不为商业化与上架 KPI 服务（个人使用优先，商店发布只是分发手段）
- 不追求覆盖所有平台（Linux / Web 暂不在计划内）
